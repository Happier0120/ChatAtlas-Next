## 1. 产品定位与愿景

ChatAtlas-Next 致力于为经常使用 AI 处理复杂或开放性问题的个人用户，提供一个具有用户账户和 Project 工作空间、可自主掌控的 AI 对话应用。

用户能够按照自己的意图展开不同的讨论方向，组织讨论之间的关系，回顾、检索和复用已有讨论，并通过自己授权的模型服务商 API Key，灵活运用 AI 能力。

我们希望将这些能力结合为可以持续探索、组织和利用的个人思考工作空间。

产品关注用户对讨论过程的自主性与掌控力。理解问题、形成判断、获得灵感或完成工作都是可能产生的收益，其具体意义由用户结合任务判断，不设统一的认知结果门槛。

## 2. 目标用户

初期目标用户的候选定义：

> 经常使用 AI 处理复杂或开放性问题，习惯通过多轮、多方向讨论逐步探索，并希望对讨论过程、历史内容和 AI 使用方式拥有更强掌控力的个人用户。

同时覆盖目标明确的任务与围绕兴趣的自由探索，暂不以特定职业限定用户群体。发起人是首位研究对象；其他用户是否具有相似问题、使用意愿和持续使用价值仍需验证。

## 3. 核心问题与机会

以下是产品机会的候选问题域，并非全部经过验证的市场事实。

| 候选问题域 | 希望理解和改善的困难 | 当前证据状态 |
| --- | --- | --- |
| 多方向讨论难以展开和管理 | 探索相关问题、比较不同方向、接续此前讨论时存在阻力 | 返回主线停点已有较详细的单人访谈；整个问题域仍待验证 |
| 历史讨论难以组织、定位和复用 | 讨论积累后难找回内容、理解关系并继续使用 | 已有用户自述，组织与复用过程尚未系统研究 |
| AI 能力的使用和组合不够灵活 | 模型、Prompt、Skill 的使用方式可能难以适应不同讨论需要 | 已表达相关意愿并提出构想；实际限制与收益尚待验证 |

“快速返回主线停点”是其中一个具体场景，不代表全部产品问题。账户体系、BYOK 和 Project 是已明确的目标产品要求，该决策本身不构成市场验证。

## 4. 核心价值主张

- **展开：** 按自己的意图探索不同问题、方向和方案，并接续需要继续的讨论。
- **组织：** 按主题或任务管理讨论，理解讨论之间的关系，方便回顾、检索和继续。
- **利用：** 复用讨论成果，灵活运用模型、Prompt 和 Skill，支持后续探索与工作。

三项价值共同服务于用户对讨论过程的自主掌控。“把问题想清楚”保留为希望支持的上层收益，具体成果因用户与任务而异。

## 5. 已明确的目标产品能力

以下属于用户明确提出的目标要求，详细业务规则与首版范围仍待后续发现。

### 用户账户体系

- 支持注册、登录和个人账户管理。
- 不同用户的 Project、对话历史、模型配置等个人数据必须相互隔离。

### 用户自带模型 API Key（BYOK）

- 登录用户能够配置希望使用的模型服务商及对应 API Key。
- 通过用户授权的 API Key 调用相应模型，不默认所有用户共用平台提供的模型密钥。
- DeepSeek、OpenAI、xAI 等是候选供应商，不代表首版必须全部支持。

密钥安全底线：

- 已保存密钥不得在普通界面中完整显示。
- 不得通过日志或错误信息泄露密钥。
- 不得明文持久化存储密钥。
- 不得使密钥被其他用户访问。

具体加密、存储和密钥管理方案留待技术设计。

### Project 工作空间

- 用户能够创建和管理多个 Project，分别组织不同主题或任务的讨论。
- 一个 Project 可以包含多条独立 Conversation，以及由 Fork 产生的对话分支。
- 一个 Project 可以容纳多棵独立对话树。
- Project、Conversation、Turn 是不同概念，不得混为一谈。

Fork 分支与 Conversation 的具体关系、上下文使用规则尚未确定。不因同属一个 Project 就推定所有讨论自动共享全部上下文。

## 6. 候选产品能力及价值映射

此图包括三项明确目标要求和七项用户提出的产品构想。价值关联不代表交付承诺、优先级、MVP 范围或已经完成 Feature Discovery。稳定编号和原始构想见 [Idea Inventory](idea-inventory.md)。

| 编号 | 能力 | 状态 | 主要价值关联 |
| --- | --- | --- | --- |
| R1 | User Management | 已明确目标，规则待细化 | 为个人讨论与配置提供账户归属和隔离基础 |
| R2 | Model Provider / API Key Management | 已明确 BYOK 方向，范围待细化 | 自主授权和选择 AI 能力，支撑利用 |
| R3 | Project Workspace | 已明确目标，规则待细化 | 按主题或任务组织多条讨论与对话树，支撑三项价值 |
| I1 | 对话工作台 | 用户提出的构想 | 为发起、接续和使用讨论提供连贯工作环境 |
| I2 | 可视化对话地图 | 用户提出的构想 | 理解讨论方向与关系，支撑展开和组织 |
| I3 | Fork 与分支管理 | 用户提出的构想 | 从已有讨论探索不同方向并保留关联 |
| I4 | Prompt 工程 | 用户提出的构想 | 表达意图、调整提问方式并复用有效输入 |
| I5 | Skill Bot | 用户提出的构想 | 将可复用指导方式用于不同讨论需要 |
| I6 | 多模型服务 | 用户提出的构想 | 按讨论需要使用模型能力，探索不同回应和方向 |
| I7 | 历史检索 | 用户提出的构想 | 找回讨论，支持接续和复用 |

R2 侧重授权与配置，I6 侧重讨论中如何使用模型能力。具体边界与交互方式尚未确定。

## 7. 关键假设与验证方向

### 产品级价值验证

| 维度 | 候选验证方向 |
| --- | --- |
| 展开 | 能否按意图顺畅探索多个讨论方向，并接续需要继续的讨论 |
| 组织 | 能否定位历史内容、理解讨论关系，并继续使用已有讨论 |
| 利用 | 模型、Prompt、Skill 及讨论复用是否帮助用户更有效地进行讨论 |
| 持续价值 | 是否愿意在自然任务中反复使用，而不仅认可概念 |
| 首次使用 | 能否理解并完成账户、Project 和模型授权所需操作；不预设操作顺序 |
| 使用底线 | 回答质量不明显下降；讨论保持预期的上下文完整性；个人数据和密钥满足隔离与安全要求 |

回答质量、数据隔离和密钥安全已有明确要求。上下文完整性的具体含义和使用规则仍待细化；本稿不决定上下文策略。

现阶段不设缺乏依据的量化门槛。“10 秒内返回主线停点”仅是局部场景的候选标准，证据与限制保留在研究基线中，不作为整款产品的主要成功标准。

### 待验证假设

- 其他目标用户也需要更强的讨论自主性与掌控力。
- 三个候选问题域在不同任务中具有实际价值。
- 候选能力带来的收益足以抵消学习和操作负担。
- 目标用户愿意且能够使用自己的模型 API Key。
- 在回答质量得到保留的前提下，过程改善能够支持持续使用。
- 相比现有工具及其替代用法，产品能提供值得改变使用习惯的明确改善。

当前主要依据是发起人的访谈、自述经历和意愿表达，尚不能证明市场需求、实际留存或候选能力的有效性。

## 8. 当前边界与尚未决定的事项

- **首次使用顺序：** 注册、配置 API Key、创建 Project、New Chat 的具体路径留待 User Journey Mapping。当前不规定 API Key 配置是创建 Project 的前置条件。
- **详细规则：** 账户生命周期、Project 管理、配置作用范围、Fork 与 Conversation 的关系、上下文使用规则。
- **实现范围：** 详细 Feature List、MVP 范围、供应商覆盖、实施顺序与排期。
- **技术方案：** 认证技术、数据库、系统架构、加密与密钥管理方式。
- **商业安排：** 定价及其他商业模式。

目标能力不代表必须以完整形态进入首版。后续范围评估须尊重数据隔离、密钥安全和回答质量底线。

旧 ChatAtlas 只作参考，其代码、原型及详细决策不自动成为新项目需求。当前仅迁移并审核文档基线，不开展 User Journey Mapping、Feature Discovery、Spec、Tickets 或业务代码开发。
