用户调整工作顺序：MVP Planning 已完成，Conversation、Turn、Fork 已有部分领域建模，但账户、BYOK、Project、生成状态等尚未系统发现；暂不直接制作整款 MVP 的详细 UX/UI 原型。先检查覆盖情况，再按明确功能主题逐步发现，只对重要决定提问，不按固定题数访谈。Feature Discovery 与 UX/UI 可以交替推进，具体交互应建立在对应功能行为上，并通过原型验证。

本轮先完成只读覆盖检查，随后用户回复“可以，开始吧”，开展 Q1～Q34 的讨论。下文提供可独立阅读的决定摘要、题号与实际确认回复，不冒充完整逐字访谈。Agent 提出的取舍理由与用户的确认分别记录，不推断用户未表达的动机。

落档前用户审核了按主题汇总的结果，并对“新增本文件、补充 GLOSSARY、仅对符合标准的重要取舍记录 ADR”的写入请求回复：“可以的，我授权了”。该授权允许本次文档落地与必要导航更新，不将整理稿自动标为 Approved，不包含 Git Commit、Push、Spec、Tickets 或业务代码实现。

本轮使用已安装的 Matt Pocock `grill-with-docs` 所引用的 `grilling` 与 `domain-modeling`。前期只读要求优先，讨论过程中未写文件；本次获得写入授权后统一落档。不使用 Superpowers brainstorming，不访问或同步 Notion，不继承旧 ChatAtlas 未重新确认的规则。

## 4. 规则之间的共同解释

### 4.1 身份、密钥与调用

邮箱验证是进入个人空间的前提；Key 是模型调用条件，不被设为创建 Project 或查看已有讨论的前提。保存 Key 不等于测试通过，测试通过不保证后来每次调用成功；失败的测试也不成为永久发送门槛。已有密钥展示、日志、错误、持久化和跨用户隔离的安全底线全部保留。

替换或移除 Key 不改变已有讨论的归属与内容，也不自动停止已发出生成。应用内导航继续生成；主动退出标记已停止；会话失效、刷新或关闭按中断处理。会话级规则只约束当前会话，页面级规则只约束当前页面，不能推导出退出其他设备或所有设备后台任务的规则。保持登录与关闭页面会中断生成可以同时成立。

### 4.2 Turn、异常历史与再次提交

正常完成、已停止、失败、中断必须可区分；未完成问答仍可作为 Turn 留在历史中，包括只有已提交 Prompt、尚无 AI 内容的情况。未确认提交成功的输入与已提交但生成失败的 Turn 不混为一谈。

后续 Prompt 追加新 Turn，必要历史应能包含此前已提交 Prompt、保留部分及其未完成状态。该要求不决定上下文组装、窗口、截断或摘要算法，也不承诺无限历史全部送入模型。重新提交原 Prompt 是按当前历史再次提问，不是恢复原流式生成或复现原请求快照；不覆盖原异常 Turn。此决定不泛化为所有既有 Turn 的编辑／同步规则。

### 4.3 准备、保存草稿与创建讨论

准备新讨论、保存未提交输入、提交 Prompt 是不同意图。点击 New Chat 或准备 Fork 时，不因此形成已保存的 Conversation；手动保存仅保存输入草稿，Fork 草稿还保留来源 Conversation／Turn。首次 Prompt 发送成功时，新的 Conversation 与该 Prompt 成为已保存讨论；即使之后生成失败，讨论仍存在。这里描述产品成功边界，不规定数据库事务或 API 顺序。

已有 Conversation 的输入草稿归属该 Conversation；尚未建立 Conversation 的输入草稿归属当前 Project，独立 New Chat 与 Fork 共用一份新讨论输入草稿。草稿不进入模型上下文或地图。发送成功只清除本次已发送版本，不清除期间另行编辑或保存的下一条输入。手动保存版本跨重新登录可恢复；未保存修改仅在应用内切换时暂存，离开可能丢失时须保护与提醒，不推导为自动持久化或草稿版本历史。

### 4.4 Fork、共同历史与导航

沿用 ADR-0001／0002：Fork 创建独立 Conversation，共同历史仍是相同 Turn，后续新增互不自动加入；地图节点代表 Turn。新增 FD-31／32 决定可用来源及来源 Conversation 的确定范围。T2 即使共同属于 A、B，也必须明确这次 Fork 的来源是哪条讨论；单纯浏览节点不能唯一推定来源或发送目标。

例：A 为 T1 → T2 → T3，B 为 T1 → T2 → T4。从 B／T2 准备 Fork 时，草稿记录 B／T2；首次新 Prompt 成功后形成 C，具有共同历史 T1、T2 及新 Turn，并保留 B／T2 关联。不能把 A 的 T3、B 的 T4 因同 Project 或来源关联自动加入 C。必要上下文构造方式仍待技术设计。

Resume 恢复的是上次 Project 与发送目标 Conversation，并定位其当前末尾，不承诺恢复任意历史浏览 Turn。具体恢复草稿的入口，以及新讨论准备态中怎样避免误把输入发往旧发送目标，须在 UX 中明确。

以下是对已确认行为的场景化解释，供文档审核和后续 UX／工程验证使用，不是正式 Feature Spec、完整测试用例或已执行验收结果。

| 场景 | 应重点核对的行为 | 追溯 |
