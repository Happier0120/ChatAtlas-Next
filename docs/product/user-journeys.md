### 阅读与研究边界

- **As-Is：** 用户报告的实际经历，不等于独立观察。证据编号 B01～B08 来自研究基线第 4 节，不受此前逐题访谈弃用影响。
- **To-Be：** 用户希望改善的体验。已明确意愿与 Agent 提出的候选体验分别标明，不把后者写成用户决定。
- **产品机会／解决方案假设：** 可能改善体验的方向及相关构想，尚未证明有效，不构成功能承诺。
- 高层级阶段可以往返、跳过或暂停，不是强制操作流程。完整端到端骨架不代表每一步都已有行为证据。
- 基础对话不依赖 Prompt／Skill 增强；D 探索可选能力的价值，不是 A 或其他旅程的必经环节。
- 仅针对影响整体旅程结构或暴露重大需求缺口的问题补充研究；具体行为规则与交互留待 Feature Discovery／UX/UI。
- 当前材料主要来自一位发起人的自述，没有独立外部用户验证、行为观测或真实留存测量。

## 2. 高层级旅程全景

| 旅程 | 用户目标与情境 | 高层级活动骨架 | 当前状态 |
| --- | --- | --- | --- |
| A．围绕一个问题展开多个方向，并继续探索 | 面对复杂任务或好奇点，深入相关问题、概念与方案，自主决定继续哪里 | 带着问题开始 → 遇到相关问题 → 深入方向 → 在方向之间往返 → 用于当前需要或暂停 | 五阶段结构已认可；证据与解决方案仍待验证 |
| B．在多个主题或任务之间切换，长期接续讨论 | 同时或先后推进不同主题，分别组织并在需要时继续 | 产生新的或持续的需要 → 确定讨论归属 → 开展讨论 → 暂停或切换 → 回来继续推进 | 高层级结构已批准；证据与方案待验证 |
| C．找回过去的讨论，用于眼前的问题 | 对历史内容记忆不完整，希望找回并实际用上 | 产生查找需要 → 根据记忆寻找 → 辨认内容与背景 → 判断适用性 → 接续或复用 | 高层级结构已批准；证据与方案待验证 |
| D．讨论效果不理想时，调整方法并继续探索 | 回答不符合自己的需要，希望尝试调整并判断是否改善 | 发现不满意 → 判断哪里不合适 → 按需尝试调整 → 判断效果 → 继续或停止尝试 | 高层级结构已批准；不预设增强能力有效 |
| E．首次使用个人 AI 工作空间，完成一次有用的讨论 | 首次尝试产品，处理当下问题并判断是否值得回来 | 带着真实需要了解产品 → 完成必要准备 → 开始讨论 → 获得有用结果 → 决定是否回来 | 高层级结构已批准；不预设设置顺序 |

这些旅程可以衔接：A 可能发生于 B 的某次讨论中，C 可能帮助 B 接续，也可能服务新任务；D 是按需调整的情境；E 关注首次获得价值。它们不是五套彼此隔离的功能模块，也不是规定的先后顺序。

## 3. Journey A：围绕一个问题展开多个方向，并继续探索

**状态：高层级结构已获认可；证据与解决方案仍待验证。**

### 用户情境与最终目标

已知具体案例：用户希望通过 ChatGPT 获得使用 Codex 和 Matt Pocock Skills 开发 ChatAtlas 的指导，讨论中又发现需要研究产品规划。相关规划可能是推进开发的必要前提，不能统一视为无关跑题（B01）。

目标是深入必要的问题、概念或备选方向，自主决定继续哪里，并将讨论用于当前任务，或在合适时暂停。自由探索也在 A 的候选覆盖内，不要求固定产出；但具体非开发事件仍不足（B07）。实际案例最终如何应用讨论成果没有完整记录。

### 五阶段地图

| 活动阶段与用户阶段目标 | As-Is：经历、困难与证据 | To-Be：希望改善的体验 | 潜在产品机会与构想关联 |
| --- | --- | --- | --- |
| 1．带着问题开始讨论：获得对当前任务有帮助的回应 | B01：通过 ChatGPT 讨论开发指导。如何开始、首轮回答如何，材料不足，不补写 | 已明确原则：直接提问和讨论，无须先执行澄清、优化或 Skill 流程 | 直接开始和持续讨论的基础能力；I1 对话工作台 |
| 2．遇到值得深入的相关问题：决定是否进一步探索 | B01：开发讨论中出现产品规划。B03：有比较方案、理解概念的需要；不代表均发生于同一次案例 | 已表达意愿：按自己的意图展开相关问题，不为维持单一线索而放弃探讨 | 支持相关方向展开并保留与原讨论的联系；I1、I2 可视化地图、I3 Fork，具体方式待验证 |
| 3．深入选定方向：完成当前需要的探讨 | B03：用过 Fork，但跳转麻烦，仍经常混聊。B01：规划与开发讨论交织，体验割裂；不能全部归因于工具 | 已表达意愿：深入相关问题，同时掌控不同讨论方向及上下文 | 减少分开讨论与保持连贯之间的操作负担；I1、I2、I3；不规定每次深入都创建分支 |
| 4．在不同方向之间往返，继续需要的讨论：转回当前关注点 | B04：回到正确会话仍可能需要寻找离开前停点。B05：有反复翻找的自述，未经计时或日志验证 | 已表达意愿：方便找到继续位置，自主返回原讨论或转向另一方向 | 降低定位与接续成本，帮助理解关系；I1、I2、I3，必要时关联 I7 历史检索 |
| 5．将讨论用于当前需要，或暂时停下：自主判断如何结束本次活动 | 没有完整记录本案例如何使用成果、采取何种行动或暂停；不补造实际终点 | 已明确价值方向：用户自行判断有用与否及是否继续，不要求统一认知或决策结果 | 支持已有讨论服务后续需要；I1、I2，与 B 的持续接续、C 的历史复用衔接，具体能力待验证 |

### 证据限制与后续发现边界

- B01 是具体案例，B03～B06 是相关补充自述，不能拼接成一次已观察的完整行为记录。
- “快速返回主线停点”主要对应第 4 阶段，不代表 A 的全部目标或整款产品愿景。
- 回答质量不能明显下降是明确使用底线（B06）；不将“10 秒”扩展为整条旅程的统一成功指标。
- 潜在机会没有证明地图或 Fork 的具体形式有效，也不意味着用户必须先整理方向再开始讨论。
- 留待 Feature Discovery：讨论方向与 Fork／Conversation 的具体关系、上下文使用规则、定位与导航行为、暂停与后续利用的支持方式。
- Prompt Assistant、澄清建议、方向推荐、Skill Bot 的行为规则不在 A 中决定。E1 跨模型 Fork 仅作为关联 I3／I6 的待验证场景，不是 A 的必要步骤。
- 不继续针对 A 开展细粒度访谈。

## 4. Journey B：在多个主题或任务之间切换，长期接续讨论

**状态：高层级结构已批准；证据与解决方案仍待验证。**

- **用户情境与目标：** 个人用户同时或先后推进多个主题、任务，希望分别组织讨论，并在暂停、切换后回来继续。
- **主要活动阶段：** 产生新的或持续的需要 → 确定讨论归属 → 开展相关讨论 → 暂停或切换任务 → 回到对应讨论并继续推进。
- **As-Is／已知困难：** B04 支持接续时寻找停点的局部困难，但不是长期多项目过程的完整证据。尚无充分材料证明用户目前如何组织多个任务、如何切换或因此遭受什么困难。
- **To-Be：** 已明确要求 R3：以多个 Project 组织不同主题或任务，一个 Project 容纳独立 Conversation 和多棵对话树。候选体验是减少重新找到相关讨论的负担；具体分类方式与效果未确认。
- **产品机会／解决方案假设：** 通过清楚的讨论归属和关系支持长期接续，降低切换后的查找成本。关联 R3、I1、I2、I3，必要时关联 I7；不推定项目内自动共享全部上下文。
- **证据限制与开放事项：** Project 要求来自明确产品决策，不是用户行为验证。何时开始新主题、沿用旧讨论或寻找历史内容仍需检验；完整跨时间实例不足，不编造组织习惯。具体管理规则和交互留待 Feature Discovery。

## 5. Journey C：找回过去的讨论，用于眼前的问题

**状态：高层级结构已批准；证据与解决方案仍待验证。**

- **用户情境与目标：** 当前任务需要参考历史讨论，但只记得大致内容；希望找到相关讨论，判断背景和适用性，并实际接续或复用。
- **主要活动阶段：** 产生查找需要 → 根据记忆寻找 → 辨认相关内容与背景 → 判断对当前需要是否适用 → 接续或复用。
- **As-Is／已知困难：** B02：有时忘记关键词，只剩模糊印象，需要反复滚动查找。现有材料没有完整记录找到之后如何辨认和使用。
- **To-Be：** 已表达意愿是方便回顾、检索和复用。能确认内容适用于当前需要，是本轮整理的候选体验，尚未获得独立行为验证。
- **产品机会／解决方案假设：** 支持利用已有线索找回讨论，并理解必要背景，避免将“找到”直接等同于“用上”。关联 I7、I2、I1、R3；E4 是对应问题或机会，不预设语义检索、摘要、导出或其他实现。
- **证据限制与开放事项：** 证据主要支持查找困难，不足以证明某种检索或复用方式有效。“继续原讨论”和“用于新任务”可能形成不同分支，尚未决定是否需要拆分。具体查找、定位与复用规则留待 Feature Discovery。

## 6. Journey D：讨论效果不理想时，调整方法并继续探索

**状态：高层级结构已批准；证据与解决方案仍待验证。**

- **用户情境与目标：** 用户发现回应不符合自己的需要，希望尝试调整，判断是否改善，再决定继续或停止当前尝试。
- **主要活动阶段：** 发现不满意 → 判断哪里不合适（可能仍不明确）→ 按需尝试调整 → 判断效果 → 继续讨论或停止尝试。
- **As-Is／已知困难：** B08：用户报告过不满意回答，并认为提示词可能是原因，提出 Prompt 优化与 Skill 预填。没有充分具体案例证明根因，也没有完整的实际调整过程。
- **To-Be：** 已表达意愿是灵活运用 AI 能力；本轮明确增强能力可选。用户也可以继续直接提问，不需要识别根因或启用增强后才能继续。
- **产品机会／解决方案假设：** 按情境支持用户调整表达或 AI 使用方式。I4 Prompt、I5 Skill Bot、I6 多模型可能有价值，但均不预设必要或有效；I1 支持继续直接讨论。涉及授权时关联 R2；E1 跨模型 Fork 仅待场景验证。
- **证据限制与开放事项：** 不把回答不佳统一归因于 Prompt，也不要求先执行优化或切换模型。改善是否足以抵消额外操作负担未验证；主动采用增强的其他场景亦不足。具体优化、澄清、Skill 触发和效果比较方式留待 Feature Discovery。

## 7. Journey E：首次使用个人 AI 工作空间，完成一次有用的讨论

**状态：高层级结构已批准；证据与解决方案仍待验证。**

- **用户情境与目标：** 首次尝试 ChatAtlas-Next，带着当下问题进入产品，希望完成一次自己认为有用的讨论，并判断是否值得回来。
- **主要活动阶段：** 带着真实需要了解产品 → 完成必要准备 → 开始讨论 → 获得自己认为有用的结果 → 决定是否回来继续。未获得有用结果也可能结束本次尝试，实际行为待验证。
- **As-Is／已知困难：** 尚无 ChatAtlas-Next 首次使用的行为证据。API Key 准备程度、设置负担、流失时点均是未知，不能写成已发生的问题。
- **To-Be：** 账户、个人数据隔离、BYOK 和 Project 属于明确目标要求；直接对话而无须增强流程属于明确原则。尽快体验与自身任务相关的价值、知道如何回来继续，是候选体验。
- **产品机会／解决方案假设：** 帮助用户理解必要使用条件并开始真实讨论，让准备过程服务于任务。关联 R1～R3、I1；E3 供应商覆盖属于范围决策，不是独立活动。
- **证据限制与开放事项：** 要求不等于首次行为已验证。注册、授权、创建 Project、New Chat 的具体顺序尚未确定，不规定先配置 API Key 才能创建 Project。调用模型所需授权仍须满足；不引入平台共享密钥、访客或试用方案。首次路径、业务规则与交互留待后续发现。

## 8. 全景覆盖与后续边界

| 检查维度 | 当前覆盖与限制 |
| --- | --- |
| 展开 | A 直接体现多方向探索，包含目标型任务与自由探索；D 支持按需调整 |
| 组织 | B 关注长期归属和接续，C 关注历史找回，A 关注方向关系；B 的实际经历证据尤其不足 |
| 利用 | C 关注讨论成果的使用，D 关注可选 AI 能力；找到内容或完成配置均不等于获得价值 |
| 首次与持续使用 | E 关注首次价值；A、B、C 可服务持续使用，但没有实际留存验证 |
| 明确目标要求 | R1～R3 支撑个人工作空间，不机械拼接成所有用户必须顺序执行的旅程 |
| 构想的待讨论场景 | E1 跨模型 Fork 尚缺实例；E2 后续 Agent 能力尚缺具体目标，暂不强行纳入；E3 是范围决策；E4 由 C 承接 |
| 旅程揭示的候选机会 | 找回后判断适用性、跨任务暂停后接续，仍需理解；先保留为机会，不自动添加功能 |
| 共同底线 | 回答质量不明显下降、个人数据隔离、密钥安全；上下文完整性的具体规则仍待细化 |

A 最直接体现当前设想的独特价值，B／C 补充长期积累价值；这是产品假设，不是竞争优势已验证。A～E 的高层级结构已获用户正式批准，作为后续 Feature Map 与 MVP Planning 的产品规划依据。As-Is 仍受单人自述和材料缺失限制，To-Be 保留用户意愿与候选体验的区别，产品机会及解决方案仍待验证；不继续细粒度访谈。
