## 2. 组织方法与状态说明

用户价值“展开、组织、利用”贯穿各 Epic，不要求一项价值只对应一个 Epic。按“用户价值 → Epic → 产品能力领域 → Feature／能力条目”组织，Foundation 承接跨 Epic 的平台基础。

| 结构 | 职责 | 主要价值 |
| --- | --- | --- |
| EP1．自主开展并深入讨论 | 开始和持续对话，展开相关方向，理解关系并在方向间往返 | 展开、组织 |
| EP2．组织、找回并利用积累的讨论 | 组织讨论归属，找回内容，通过跨功能场景支持接续与利用 | 组织、利用 |
| EP3．按需要调整 AI 使用方式 | 运用不同模型，以及可选 Prompt／Skill 增强 | 利用、展开 |
| Foundation | 用户身份、账户管理、个人数据隔离、BYOK 授权与密钥安全 | 支撑全部价值及 Epic |

Foundation 单列后仍保留独立条目和跨 Epic 依赖，避免范围规划时遗漏。其位置不代表优先级，也不预判 MVP 取舍。此处是产品能力分类，不是工程架构或模块划分。

### 条目性质

| 性质 | 含义 |
| --- | --- |
| 用户功能 | 用户可主动执行或直接体验的功能，如发起讨论、检索、配置 |
| 结构能力 | 产品支持的组织关系或运作能力，如一个 Project 容纳多条 Conversation、多棵树，以及授权模型调用 |
| 跨域保障 | 多个功能共同满足的归属、隔离、安全等保障或约束 |

保留原 Feature 编号作为能力追溯标识；编号不表示优先级、独立页面、独立开发任务或 Ticket。结构能力与保障往往由多个功能共同实现，不能机械拆成一编号一任务。

### 决策、验证与范围状态

- **目标要求：** 直接承接 R1～R3 的已明确要求，详细规则仍待发现。
- **用户构想：** 承接 I1～I7，保留探索，尚未证明具体形式有效。
- **旅程候选：** 从已批准旅程整理出的能力表达，具体 Feature 尚待后续发现。
- **补充提案：** 本次检查提出的候选缺口，不代表用户已经要求。

文档批准仅确认上述条目在产品能力图中的分类与规划位置，不将“用户构想”“旅程候选”或“补充提案”升级为已明确功能承诺。条目决策状态、验证状态与文档审核状态相互独立；所有条目的 MVP 归属均未评估。

### Journey 索引

| 编号 | 用户目标 |
| --- | --- |
| A | 围绕一个问题展开多个方向，并继续探索 |
| B | 在多个主题或任务之间切换，长期接续讨论 |
| C | 找回过去的讨论，用于眼前的问题 |
| D | 讨论效果不理想时，调整方法并继续探索 |
| E | 首次使用个人 AI 工作空间，完成一次有用的讨论 |

Journey 关联表示候选适用情境，不表示每位用户都必须执行这些功能，也不等于该关联已通过行为验证。

## 4. EP2：组织、找回并利用积累的讨论

### 4.1 Project Workspace 与讨论组织

Project 是整款产品的讨论组织基础。它归属 EP2，但同时组织 EP1 的 Conversation、分支与对话树，并为 EP3 的模型和增强能力提供讨论发生的情境。组织归属不等于配置作用范围，也不等于自动共享上下文。

| Feature ID | 用户可感知的候选 Feature／能力 | 性质 | 来源 | 关联 Journey | 决策状态 |
| --- | --- | --- | --- | --- | --- |
| PROJ-01 | 创建和管理多个 Project，分别组织不同主题或任务 | 用户功能，管理范围待细化 | R3 | B、E | 目标要求 |
| PROJ-02 | 在一个 Project 中组织多条独立 Conversation | 结构能力 | R3 | A、B | 目标要求 |
| PROJ-03 | 在一个 Project 中容纳 Fork 分支及多棵独立对话树 | 结构能力 | R3 | A、B | 目标要求 |
| PROJ-04 | 找到并切换到需要继续的 Project 或讨论 | 用户功能 | Journey B；R3、I1、I2 | B、C | 旅程候选 |

Project、Conversation、Turn 保持概念区分。PROJ-02／03 描述产品必须支持的组织结构，不各自代表一个独立操作或开发任务。Project 管理的具体操作集合、讨论能否变更归属等规则待 Feature Discovery。

### 4.2 历史检索与结果定位

负责从积累内容中查找并定位历史讨论，不把“搜索命中”直接视为完成复用。

| Feature ID | 用户可感知的候选 Feature | 性质 | 来源 | 关联 Journey | 决策状态 |
| --- | --- | --- | --- | --- | --- |
| FIND-01 | 检索历史 Turn | 用户功能 | I7 | C；也可服务 A、B | 用户构想 |
| FIND-02 | 根据消息内容查找历史讨论 | 用户功能 | I7 | C；也可服务 B | 用户构想 |
| FIND-03 | 从搜索结果定位到对应讨论位置 | 用户功能 | I7 | C、B、A | 用户构想 |

FIND-01、FIND-02 保留原始检索对象和内容范围，不代表必须建设两套搜索。其范围边界在后续发现中明确。

### 4.3 跨功能场景 SC-01：找到历史讨论后继续或利用

该场景归属 EP2，关联能力分布在 EP1、EP2；当前不另设产品能力领域。只有发现目标、职责和边界清楚的独立能力时，才考虑新增领域。

| 场景环节 | 关联 Feature | 当前覆盖与开放边界 |
| --- | --- | --- |
| 根据记忆寻找讨论 | PROJ-04、FIND-01、FIND-02 | 已有候选能力；模糊印象查找仍由 E4 保留 |
| 定位内容并辨认背景 | FIND-03、CHAT-03、MAP-01～03 | 能力上可衔接；是否足以理解背景尚待验证 |
| 判断是否适用于当前需要 | 查看内容及关系的相关能力 | 判断由用户作出；暂不添加自动适用性判断 |
| 继续原讨论 | CHAT-04；必要时 MAP-03 | 已有基础能力承接 |
| 从历史讨论展开新方向 | FORK-01、CHAT-04 | 是一种候选利用路径，不代表所有复用都必须 Fork |
| 将讨论用于其他当前需要 | 关联历史查看、定位与 Fork | 目标保留，具体方式开放；尚未识别出必须独立建设的能力 |

该场景不预设摘要、导出、知识库、自动复制上下文或讨论合并。

### 6.3 BYOK 授权与密钥保护

| Feature ID | 用户可感知的候选 Feature／能力 | 性质 | 来源 | 关联 Journey | 决策状态 |
| --- | --- | --- | --- | --- | --- |
| KEY-01 | 配置希望使用的模型服务商及个人 API Key | 用户功能 | R2 | E；支撑 A～D | 目标要求 |
| KEY-02 | 使用自己授权的 API Key 调用相应模型 | 结构能力及跨域授权保障 | R2 | A～E | 目标要求 |

KEY-02 描述模型调用必须满足的用户授权关系及运作能力，贯穿基础对话、模型运用和相关增强，不等同于独立操作或 Ticket。不默认所有用户共用平台提供的模型密钥。

该领域必须满足已有密钥安全要求：

- 已保存密钥不在普通界面完整显示。
- 不通过日志或错误信息泄露密钥。
- 不明文持久化存储密钥。
- 不允许其他用户访问密钥。

密钥更新、失效后的处理及账户生命周期相关规则仍待发现；本稿不指定加密、存储或认证方案。

| 基础聊天 | CHAT-01～04 | 支持直接提问、获得回答、查看历史和持续交流 |
| 讨论展开与组织能力 | Fork、地图、Project、历史检索 | 支持展开、组织与利用；不强制每次讨论都执行全部操作 |
| 按需模型运用 | MODEL-01 | 基础调用使用已授权模型；多模型选择与运用规则待发现 |
| 可选 Prompt／Skill 增强 | PROMPT、SKILL | 用户按需采用，不是基础聊天的前置流程 |
| 平台基础能力 | ACCT、DATA、KEY | 提供个人身份、数据隔离和模型授权保障 |

以上是产品能力性质分类，不是 MVP 分类或优先级排序。结构能力、用户功能与跨域保障可以共同支撑同一用户体验，不强求一一对应的开发边界。

## 9. 重要依赖、职责边界与共同底线

| 关系 | 需要保留的依赖或协作 | 本稿保留的开放边界 |
| --- | --- | --- |
| 账户、数据与全部 Epic | 个人讨论和配置需要正确归属与隔离 | 不确定具体首次使用步骤 |
| 模型调用与 BYOK | 调用相应模型需要有效的用户授权及供应商支持 | 不规定先配 Key 才能创建 Project |
| Project 与对话、分支、地图 | Project 组织讨论归属及多棵树；相关能力服务该组织结构 | 不推定 Project 内全部上下文共享，也不确定配置作用范围 |
| Fork 与历史上下文 | 从历史位置展开方向，需要明确分支与相关历史的关系 | Fork／Conversation 关系、继承、共享、存储及模型上下文使用规则待定 |
| 地图与讨论结构 | 地图需要表达实际讨论关系，并能定位对应内容 | 不要求只有通过地图才能开始或继续讨论 |
| 检索与查看、导航、接续 | 搜索结果需衔接到可理解、可继续的讨论位置 | 不将搜索命中直接算作复用成功 |
| Prompt／Skill 与基础聊天 | 增强应能衔接讨论，同时保持直接聊天可用 | 组合顺序、作用范围、触发方式待定 |
| 跨模型 Fork | 同时涉及 Fork、模型运用和授权 | E1 仍开放，不自动合并为交付承诺 |

共同底线如下，不能因条目分属不同 Epic 或 Foundation 而遗漏：

- **回答质量：** 不明显下降；不将流程改善替代回答质量要求。
- **上下文完整性：** 讨论应保持预期的上下文完整性；具体含义、继承与使用规则仍待发现和验证，本稿不指定上下文策略。
- **个人数据隔离：** 不同用户的 Project、讨论历史、模型配置等个人数据相互隔离，贯穿查看、检索、导航、配置和调用等能力。
- **密钥安全：** 满足第 6.3 节全部安全要求，贯穿保存、使用、展示和错误处理等环节。
