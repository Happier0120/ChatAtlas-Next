## 2. MVP 目标与核心价值假设

### 首版产品目标

让经常使用 AI 处理复杂或开放性问题的个人用户，在自己的 Project 中直接完成有价值的多轮讨论，按意图展开相关方向、理解讨论关系、往返继续，并在离开后重新进入和利用已有讨论。

首版围绕「展开—组织—利用」形成最小体验：Fork 支持展开，Project 与地图支持组织，回顾和接续让已有讨论继续服务用户需要。利用不预设导出、摘要或知识库，也不要求用户形成统一的认知或工作成果。

### 尚待验证的核心假设

- Fork、关系展示与导航结合后，能减少混聊和寻找接续位置的负担，其收益足以抵消学习与操作成本。
- 必要历史上下文正确、回答质量得到保留时，用户能在多个方向中持续开展有用讨论。
- Project 组织、地图定位与持久化接续，足以支撑首批用户的基本持续使用；首版可以暂缓内容搜索。
- 首批目标用户愿意且能够完成账户与 BYOK 准备，并使用首版支持的模型。
- 用户愿意在自然任务中再次使用，而不仅认可概念或完成一次演示。

当前主要依据是发起人的自述与产品决定，缺少独立外部用户验证、行为观测和真实留存测量。上述假设不是已经验证的结论。

## 3. 首版端到端用户体验

以下描述用户能够完成的活动，不指定页面、按钮或固定操作顺序。

1. **准备个人工作空间。** 用户建立并访问自己的账户，能够理解当前调用模型所需的条件，配置个人 API Key，并准备所需 Project。调用前须满足授权条件，但不规定先配 Key 才能创建 Project。
2. **直接开展讨论。** 在 Project 中发起 Conversation，直接输入问题，接收真实模型的流式回答并持续追问；无须先使用 Prompt 或 Skill 增强。
3. **按意图展开方向。** 从相关历史位置 Fork，使用正确的必要历史上下文深入新方向；原讨论仍能独立继续，不强制每次深入都 Fork。
4. **理解关系并往返。** 通过地图查看真实讨论关系及对应内容，定位目标位置、切换方向并继续交流；不以仅显示树形图视为完成。
5. **组织与切换。** 在多个 Project、独立 Conversation 和对话树之间找到需要的讨论，按主题或任务开展工作；Project 内不默认全部上下文共享。
6. **暂停并重新进入。** 已形成的讨论持久化。用户离开或结束当前使用后，重新进入自己的账户和 Project，能查看内容及关系、定位并接续原讨论或分支；不承诺特定的自动恢复方式。
7. **辨认不可用状态。** 条件未满足、调用失败或回复中断时，用户能够辨认状态及其对当前讨论的影响；具体恢复动作与未完成内容的处理规则后续确定。
8. **用于当前需要或结束。** 用户自行判断讨论是否有用，可以继续、用于其他工作或暂停，不以统一输出格式作为价值门槛。

### 对已批准 Journey 的覆盖

| Journey | MVP 覆盖与限制 |
| --- | --- |
| A：多方向探索 | 核心覆盖：直接讨论、展开方向、关系理解、往返、继续或暂停；不缩减为仅返回停点 |
| B：跨主题长期接续 | 覆盖多个 Project、独立讨论、多树、切换及重新进入后的接续；不承诺高级组织管理或大规模历史下的高效查找 |
| C：历史找回利用 | 支持通过已知 Project 和讨论关系回顾、定位、接续或 Fork；不包含内容搜索，不宣称完整覆盖 C 或解决 E4 |
| D：调整讨论方式 | 支持直接追问与调整表达；Prompt、Skill、多模型调整路径延后 |
| E：首次获得价值 | 覆盖必要准备、真实模型调用、有用讨论和可再次进入的工作空间；具体首次使用路径待设计 |

## 4. 纳入范围与最小交付深度

Feature ID 沿用 Feature Map，用于追溯能力，不代表独立页面、实现任务或 Ticket。结构能力与跨域保障须贯穿相关功能。

| 能力 | Feature ID／关联来源 | MVP 最小交付深度 | 保留的详细规则边界 |
| --- | --- | --- | --- |
| 账户访问与最小管理 | ACCT-01、ACCT-02；ACCT-03 最小范围；R1 | 注册、登录和访问个人工作空间；基础个人资料查看与维护限于方案 A 的最小管理范围 | 不承诺完整账户生命周期；具体资料、操作和账户状态规则待定 |
| 数据归属与隔离 | DATA-01；R1 | Project、讨论历史及模型配置归属正确，不被其他用户访问；覆盖查看、导航、保存、配置和模型调用 | 不指定认证、权限或存储技术 |
| BYOK | KEY-01、KEY-02；R2、E3 | 用户配置并授权自己的 Key，通过一家供应商的一个真实可用模型开展讨论；不默认共用平台模型密钥 | 供应商与模型待确认；配置作用范围、密钥维护与失效处理规则待定 |
| 基础聊天 | CHAT-01、CHAT-02、CHAT-03、CHAT-04；I1 | 直接发起讨论、真实流式回答、历史查看与多轮继续；不依赖增强流程 | 输入提交、生成过程及未完成回复的详细处理待定 |
| Project 组织与接续入口 | PROJ-01、PROJ-02、PROJ-03、PROJ-04；R3 | 创建、命名和基本维护多个 Project；组织多条独立 Conversation、Fork 分支和多棵独立树；找到并切换到所需讨论 | 管理操作集合、Conversation 管理及归属变更规则待定；不承诺完整生命周期 |
| Fork 与必要历史 | FORK-01、FORK-03 必要范围；I3 | 从历史位置展开新方向；必要历史上下文正确；原讨论和新分支可独立继续，并保留真实关联 | 不决定 Fork／Conversation 的身份关系、历史复制或引用、同步方式、上下文构造策略 |
| 地图查看与讨论导航 | MAP-01、MAP-02、MAP-03；I2 | 显示 Turn 对应内容、真实方向与关系以及多棵树；定位内容、切换方向并支持继续讨论 | 不决定 Card 等具体 UI、布局算法、地图入口或编辑方式 |
| 持久化与重新进入后接续 | 跨功能要求：CHAT-03／04、PROJ-02～04、FORK-01／03、MAP-01～03、DATA-01；MP07 | 已形成的讨论、归属及关系可在重新进入后查看和继续；原讨论与分支均受保障 | 不新增虚构 Feature ID；保存确认、未完成内容及重新定位的详细规则待定 |
| 必要调用条件可辨认 | GAP-01 的首版必要部分；关联 ACCT、KEY、CHAT、PROJ | 用户知道哪些必要条件尚未满足、什么影响当前调用；不以固定设置顺序代替条件说明 | 不预设引导界面、额外设置中心或自动检测方式 |
| 失败与中断可辨认 | GAP-02 的首版必要部分；关联 CHAT-02／04、KEY-02 | 用户能区分正常完成、失败和中断，理解当前状态；不把未完成结果误示为完整成功 | 详细恢复、重试、部分内容保存与后续接续规则待 Feature Discovery |

GAP-01／02 在 Feature Map 中原为待探索缺口；本轮 MP06 已明确将影响首版闭环的部分纳入范围。这是范围状态的后续决定，不回写或扩大旧文档的历史批准。

### 必须满足的安全、状态与数据一致性边界

- **身份和归属正确：** 账户访问或讨论切换不能使用户看到、修改或调用其他用户的数据与模型配置。
- **全部密钥安全底线保留：** 已保存 Key 不在普通界面完整显示，不经日志或错误信息泄露，不明文持久化，不被其他用户访问。
- **上下文与讨论对象一致：** 展示、定位、提交与后续回答应对应用户当前选择的讨论；分支继续不能意外覆盖原讨论或其他方向的内容，不默认引入无关 Project 或讨论历史。
- **关系与状态一致：** 地图、历史内容、Project 归属和实际可继续的讨论应相符；失败、中断不能冒充已完成，不能把未确认持久化的状态误示为已可靠保存。
- **持久化结果可核对：** 重新进入后，已确认保存的讨论内容及关系仍可正确访问和继续；切换方向或 Project 不应造成这些内容意外丢失。
- **范围裁剪不削弱质量：** 回答质量不得明显下降，不能用流程或地图改善替代模型回答与必要上下文的质量要求。

以上是产品交付结果边界，不确定保存时点、事务、并发、多端同步、恢复机制或具体状态机。未完成输入与部分回复如何持久化仍需后续明确。

## 5. 明确排除范围与后续候选

以下均不纳入 MVP。延后不删除原构想，也不承诺一定进入下个版本。

| 排除范围 | Feature ID／原事项 | 取舍依据与后续考虑条件 |
| --- | --- | --- |
| 历史内容检索与结果定位 | FIND-01、FIND-02、FIND-03 | 首版先验证组织、地图与接续闭环；真实积累后若查找成为主要阻力，作为优先后续候选 |
| 多模型选择、切换及多供应商覆盖 | MODEL-01；E3 的扩展覆盖 | 一个合适模型可验证讨论结构价值；使用门槛或明确模型需求证明必要时再评估覆盖 |
| Prompt 模板、澄清、优化、增强输入预览 | PROMPT-01、PROMPT-02、PROMPT-03、PROMPT-04 | 不构成基础聊天和方向接续的必要依赖；需另验证收益是否抵消操作负担 |
| Skill Bot | SKILL-01、SKILL-02、SKILL-03 | 配置、作用范围与效果未明确，独立于本次核心闭环 |
| 专门的分支草稿管理 | FORK-02 | 草稿概念及生命周期开放；不据此承诺独立草稿体系，也不据此决定普通输入的保存规则 |
| 高级分支管理 | FORK-04 | 不承诺完整分支生命周期；已有创建、查看、定位和继续由纳入能力承接 |
| 扩展节点操作与高级地图交互 | MAP-04 的独立扩展范围；MP03 | 复杂布局、批量节点操作等延后；必要查看、导航及 Fork 不因该排除被移除，也不重复计为新能力 |
| 高级账户、Project、Conversation 管理 | 超出 ACCT-03、PROJ-01 及相关讨论管理最小范围的部分 | 以端到端使用所需操作为界，不将宽泛条目当作完整生命周期承诺；具体边界后续发现 |

### 暂缓探索及仍开放的事项

- **E1：跨模型 Fork。** 场景价值与上下文边界尚未明确，首版无多模型切换，不展开该场景。
- **E2：Agent 能力。** 具体任务与边界未明确，不纳入或提前设计。
- **E3：供应商覆盖。** 首版数量边界按 MP05；具体供应商与模型仍需确认，不承诺 DeepSeek、OpenAI、xAI 全覆盖。
- **E4：模糊印象找回历史。** 问题保留，首版导航不代表已解决，不预设语义检索等方案。
- **SC-01：历史讨论接续与复用。** 保留为跨功能场景，首版只交付已知归属下的查看、定位、继续与 Fork；不单设新领域，不扩展到完整搜索、摘要、导出、知识库、自动复制上下文或讨论合并。

## 6. 跨功能依赖与主要风险

### 依赖检查

| 用户体验 | 必须一起满足的依赖 |
| --- | --- |
| 首次真实讨论 | Foundation 的 ACCT、DATA、KEY ＋ EP2 的 Project ＋ EP1 的 CHAT；GAP-01 说明必要条件，准备顺序另定 |
| Fork 后独立继续 | FORK-01／03 ＋ CHAT-03／04 ＋ PROJ-02／03 ＋ DATA-01；历史上下文与分支关系正确 |
| 地图定位并继续 | MAP-01～03 ＋ 实际讨论及 Fork 关系 ＋ CHAT-03／04；地图和对话使用同一真实关系，不能只提供展示 |
| 跨 Project 切换与重新进入 | PROJ-01～04 ＋ 历史与关系的持久化 ＋ ACCT／DATA ＋ CHAT／MAP；隔离和可接续性持续成立 |
| 条件不足、失败或中断 | GAP-01／02 的必要部分 ＋ CHAT／KEY 的状态 ＋ 持久化一致性；错误说明也须保护密钥与个人数据 |

Foundation 是这些体验的组成部分，不能因不属于 Epic 而省略。基础调用依赖 BYOK，不依赖 MODEL-01；Fork 不依赖跨模型场景，聊天不依赖 Prompt／Skill。

### 主要风险与后续处置方向

| 类型 | 风险及影响 | 后续需要取得的证据或结论 |
| --- | --- | --- |
| 技术／产品语义 | Fork 历史和上下文规则未定，可能导致背景缺失、无关历史混入或原讨论无法独立继续 | 先明确可解释的领域与上下文边界，再验证两个方向均可连贯继续；不继承旧 Fork V1 Spec |
| 技术／一致性 | 流式回复、失败、中断与持久化衔接不当，可能产生虚假完成、内容丢失或关系不一致 | 明确状态、保存与恢复要求，后续验证重新进入后的真实结果 |
| 技术／安全 | 隔离或密钥保护在导航、配置、错误等路径遗漏 | 后续对全部访问与调用路径验证隔离和安全底线，而非只检查登录和配置入口 |
| 范围 | 地图、草稿或管理条目扩展成完整编辑与生命周期系统 | 以第 3～5 节的用户结果和排除项约束范围，必要变更另行批准 |
| 用户价值 | 地图和 Fork 增加负担，用户仍选择混聊；跨时间接续未改善 | 观察真实探索、往返及后续使用，记录额外操作与未使用原因 |
| 用户价值／覆盖 | 暂无搜索或仅一家供应商使部分任务无法完成，BYOK 准备阻碍首次价值 | 记录定位失败、供应商与 Key 条件及退出原因，区分使用门槛与核心讨论价值问题 |
| 可行性 | 尚无工程架构和实现验证，产品范围获批不能证明成本、性能或交付周期 | 供应商、上下文规模与地图规模等需后续调查；当前不虚构工期或可行性验证结果 |

## 7. 用户验收场景与价值验证

### 范围级用户验收场景

以下用于核对产品交付结果，不是详细 Feature Spec 或已执行的测试；具体数据、操作、状态断言和量化门槛后续细化。

| 场景 | 应能观察到的结果 | 主要关联 |
| --- | --- | --- |
| 首次直接讨论 | 完成必要准备后，用户无需 Prompt／Skill 即可用个人授权模型获得真实回答并多轮追问 | ACCT、KEY、CHAT、PROJ、GAP-01 |
| 两个方向独立推进 | 从历史位置 Fork 后，新方向具备必要背景；原讨论和新分支分别继续，内容、关系及当前讨论对象不混淆 | FORK-01／03、CHAT、MAP、DATA |
| 地图往返与接续 | 用户能辨认真实关系，查看对应内容，定位并切换到需要的方向继续讨论，而非仅看到图形 | MAP-01～03、CHAT-03／04 |
| 多 Project 与多树组织 | 同一账户能在多个 Project 下组织讨论；一个 Project 能容纳多条独立 Conversation 与多棵树，切换后归属和内容保持正确 | PROJ-01～04、MAP、DATA |
| 离开后重新进入 | 结束当前使用后重新访问账户，已确认保存的内容和关系仍在；用户能找到位置并继续原讨论及分支 | ACCT、CHAT、PROJ、FORK、MAP、持久化要求 |
| 条件不足或调用异常 | 条件未满足、调用失败或回复中断时，用户能辨认状态，不被误导为已完整成功；错误不泄露密钥 | GAP-01／02、KEY、CHAT |
| 跨用户隔离与密钥保护 | 另一账户不能访问前一账户的 Project、历史与模型配置；密钥在展示、日志、错误、保存与调用中满足安全底线 | DATA-01、ACCT、KEY |

### 用户价值验证思路

- 使用真实的复杂或开放性问题，同时允许任务推进与自由探索；不把所有人限定为开发场景，不重新恢复已弃用的逐题访谈。
- 观察用户是否自然展开方向、能否理解关系并找到要继续的位置，以及是否仍因操作负担选择混聊；不能只统计 Fork 次数或展示地图。
- 在可比的模型与任务条件下，核对必要上下文和回答质量，区分模型差异与产品组织方式造成的影响。
- 安排跨时间的重新进入与自然后续使用，观察讨论是否被实际接续，以及用户是否愿意再次使用；一次演示完成不等于持续价值。
- 由用户判断讨论对当前需要是否有用，记录定位失败、设置阻力、放弃原因及额外操作成本，作为后续范围调整依据。
- 产品可用性、用户价值、回答质量与安全验证分别记录；概念认可不替代行为证据，价值认可不替代安全验收。

当前不设缺乏依据的转化、留存或性能门槛。历史「10 秒内返回停点」仅为局部场景候选标准，不作为整款 MVP 的已批准验收阈值。
