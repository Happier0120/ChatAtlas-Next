# ChatAtlas-Next — Product Idea Inventory

- **Version:** 0.1
- **Status:** Approved
- **Last updated:** 2026-11-17（Asia/Shanghai）
- **Review:** 2026-11-17 用户审核五文件基线后明确回复“批准了，提交 commit”；仓库整理版获批作为正式 Discovery 输入，不代表 MVP 范围或已完成 Feature Discovery。
- **Basis:** 本会话构想库及三项审查调整；来源 S1—S9 见 [研究基线](../research/product-discovery-baseline.md)。

## 用途与状态

采用“产品构想驱动、用户场景验证、功能渐进细化”的工作方式。构想可以帮助发现具体场景，但不等于已完成 Feature Discovery、已验证市场需求或已承诺 MVP 范围。

本库保留稳定编号，区分：已明确的目标要求（R）、用户明确提出的产品构想（I）、不同性质的待探索事项（E）。分类不表示优先级。

## 1. 已明确的目标要求

以下是目标产品要求，详细业务规则及首版范围尚未确定。

| 编号 | 要求 | 已明确内容 | 来源 |
| --- | --- | --- | --- |
| R1 | 用户账户体系 | 注册、登录、个人账户管理；不同用户的 Project、历史、模型配置等个人数据隔离 | S2 |
| R2 | 模型服务商与 API Key 管理（BYOK） | 登录用户配置并授权自己的模型密钥；不默认所有用户共用平台密钥；遵守密钥安全底线 | S2、S3 |
| R3 | Project 工作空间 | 管理多个 Project；每个 Project 可含多条独立 Conversation、Fork 分支及多棵独立对话树；Project、Conversation、Turn 不等同 | S2 |

R2 的安全底线：已保存密钥不在普通界面完整显示，不通过日志或错误信息泄露，不明文持久化存储，不被其他用户访问。具体安全方案后续技术设计。

共同边界：回答质量不能明显下降；上下文完整性需后续验证和细化，不推定同一 Project 的所有讨论自动共享全部上下文。首次使用顺序尚未确认，不规定先配置 API Key 才能创建 Project。

## 2. 用户明确提出的产品构想

本分类替代此前“核心设计构想”的名称，避免被误解为 MVP 核心功能。统一状态为：**用户明确提出并保留探索，具体规则与形式尚未完成 Feature Discovery**。

| 编号 | 产品构想 | 原始候选范围 | 价值关联 | 来源 |
| --- | --- | --- | --- | --- |
| I1 | 对话工作台 | New Chat、模型调用与流式回复、对话继续与历史 | 展开、组织、利用 | S1 |
| I2 | 可视化对话地图 | Turn Node Card、多棵 N 叉树、节点操作与路径导航 | 展开、组织 | S1 |
| I3 | Fork 与分支管理 | 历史位置 Fork、草稿管理、共享历史与分支生命周期 | 展开、组织 | S1 |
| I4 | Prompt 工程 | Prompt 模板、可选澄清与优化、提交前预览 | 展开、利用 | S1 |
| I5 | Skill Bot | 节点或分支 Skill 预填、Skill 开关与配置 | 利用 | S1 |
| I6 | 多模型服务 | 按讨论需要使用不同模型能力 | 展开、利用 | S1 |
| I7 | 历史检索 | Turn 搜索、消息内容检索、搜索结果定位 | 组织、利用 | S1 |

“共享历史”“分支生命周期”等只保留用户构想名称，不导入旧项目的详细规则。R2 侧重模型使用授权与配置，I6 侧重讨论中如何使用模型能力。

Project 容纳多棵独立对话树已是 R3 的目标要求；如何呈现和操作这些树仍是 I2 的设计构想。

## 3. 待探索事项：保留原始信息并区分性质

| 编号 | 原始事项 | 性质与状态 | 关联及来源 |
| --- | --- | --- | --- |
| E1 | 跨模型 Fork | 关联 Fork 与多模型服务的场景构想；何时需要、目标和收益尚待验证 | I3、I6；S1 |
| E2 | 后续 Agent 能力 | 远期探索方向；具体任务、边界与收益尚未明确 | I5；S1 |
| E3 | 供应商覆盖 | 待确定的实施范围决策；DeepSeek、OpenAI、xAI 等为候选，不承诺首版全覆盖 | R2、I6；S1、S2 |
| E4 | 仅有模糊印象时找回历史讨论 | 用户问题或产品机会；已报告缺少关键词时难找历史，具体解决方式开放 | 可能关联 I7，也可揭示其他能力；访谈摘要 B02 |

E4 不预设语义检索或其他技术方案。E3 不是新的用户问题；不将这四项视为相同成熟度的功能需求。

## 4. 证据与决策状态

- 已明确目标要求来自用户决策，不代表市场已验证。
- 返回主线停点有较详细的单人经历；历史查找和回答不满意有用户自述。
- 自由探索、非开发任务及其他构想的具体场景，尚缺充分实例或行为观测。
- 持续使用与“10 秒内接续”的表达属于意愿或候选门槛，不是实际留存、测量结果或性能承诺。

具体经历、数值来源及局限见 [研究基线](../research/product-discovery-baseline.md)，产品级假设见 [Product Vision](product-vision.md)。
